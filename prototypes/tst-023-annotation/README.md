# PROTOTYPE — TST-023 批註互動

拋棄式原型，只存在於 `prototype/tst-023-annotation` 分支，不合併進 main。

## 要回答的問題

在離線 HTML Review Projection 上提出 Revision Request，哪一種互動最順手（#86）？

## 做法

`build.mjs` 讀取 TST-022 產出的真實 BR-TST-022 `review.html`（路徑寫在檔內，需自行調整），
移除 CSP、注入 `annotate.css` 與 `annotate.js`，以 `?variant=` 與底部切換列切換三種互動：

* A 行內按鈕：每個帶定位點的元素旁「＋意見」，表單就地展開。
* B 右側抽屜：選取多個目標或「整批」，表單與意見清單在抽屜。
* C 選取文字後彈出：選字跳出「提出意見」，置中對話框，旁註編號。

三者共用匯出（下載＋可複製文字框）、匯入還原、去重、待比對、localStorage 輔助暫存與未匯出提示。
`verify.mjs` 以 Chrome 跑建立、匯出、清除暫存、匯入的冒煙流程。

## 結論（2026-09-18）

第一版採 B 右側抽屜為主（多目標、整批、意見清單、跳回原文），加上 A 的行內「＋意見」
作為快速入口：點擊即以該區塊為目標打開抽屜。窄螢幕排版與按鈕顯示方式等細節之後再改善。
