# PraxisBound 0.10.0

`0.10.0` renames the Protocol from ForgeFlow to PraxisBound. It is **Breaking**
for every repository adopted under ForgeFlow `0.9.0`, because the adoption
marker, the decision-root variable, and the Codex activation snapshot all carry
the old identity. Nothing else in the Protocol changes: `make verify`
semantics, the required entrypoints, and Story, verification, and Handoff
contracts are the same as `0.9.0`.

## Adoption marker

A fresh adoption writes `specs/.praxisbound-adoption` only. An existing
adoption migrates by running the new Bootstrap with `--upgrade`:

```sh
./scripts/bootstrap --upgrade /path/to/repository
```

It accepts a regular, readable legacy `specs/.forgeflow-adoption` carrying
`version=0.9.0` as one-way migration input, writes the new marker with the same
revision, and removes the old one. Both markers present, unsafe paths, or
malformed legacy data are refused before any write. Do not create the new
marker by hand.

## Decision root

Replace `FORGEFLOW_DECISIONS_ROOT` with `PRAXISBOUND_DECISIONS_ROOT`. A
non-empty old variable is rejected rather than aliased, so a repository that
keeps the old name fails `scripts/story-check` instead of silently falling back
to `specs/decisions/`.

## Codex activation

The activation snapshot moves from `.agents/skills/forgeflow` to
`.agents/skills/praxisbound`. Re-run activation to migrate it:

```sh
./scripts/codex-activate /path/to/adopted-repository
./scripts/codex-activate --apply /path/to/adopted-repository
```

ForgeFlow artifacts are migration inputs only. Activation validates the legacy
directory's membership, checksums, identity, and managed `AGENTS.md` block
before writing, and refuses edited, incomplete, or dual-identity targets.
Repositories that never ran activation have nothing to migrate here.

## Upgrading and rollback

Retain a recovery point before upgrading. To roll back before publishing the
upgraded repository, restore the complete pre-upgrade checkout, including the
legacy marker and the old environment variable. The full procedure is in
[Upgrading an adopting repository](../upgrading.md) (`docs/upgrading.md`).

## Reference Tooling

The npm packages `@praxisbound/core` and `@praxisbound/cli` are Reference
Tooling, versioned independently of the Protocol. They are not part of this
release and are not required to adopt it; the portable shell entrypoints remain
sufficient. Maintainer-only release tooling changes made after the rename,
including the retirement of the legacy release-check implementation, leave the
Protocol surface and this version unchanged.
